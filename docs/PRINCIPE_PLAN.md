# План реализации по principe.md

> Анализ расхождений между механиками из `docs/principe.md`, текущими правилами (`docs/Правила.md`), и реализованным кодом.
> Дата: 2026-08-11.

---

## 1. Общая оценка

Текущий код покрывает ~40% механик из `principe.md`. Реализованы: базовая модель грядок (Plot), посадка на клетке поля (qty=1), розыгрыш 1 случайной карты кристаллов, инвестирование крестиков, сбор урожая (но без пополнения склада), производства-шатры (3 типа), строительство шатров, крафт товаров, заказы (генерация + выполнение), склад товаров, каталог растений/товаров/животных/питомцев в админке, нормы кристаллов (пресеты 1–8 + пользовательские), система монет.

## 2. Что НЕ реализовано и расходится с principe.md

### 2.1. Количество растений на грядке (High)
- **principe.md:** игрок выбирает количество растений (1–20) при посадке. Норма = кристаллы × количество.
- **Сейчас:** `plant_on_cell` хардкодит `qty=1`. Поле `Plot.qty` есть, но не используется.
- **Нужно:** добавить `qty` в запрос посадки, пересчитывать `required = crystal_norm × qty`.

### 2.2. Розыгрыш карт по уровню растения (High)
- **principe.md:**
  - Уровень 1: 1 карта (без сокровищ).
  - Уровень 2: 2 карты (без повторов, сокровища возможны).
  - Уровень 3: 3 карты (без повторов, сокровища возможны).
  - Есть 3 бонусные карты «сокровищ».
- **Сейчас:** всегда 1 случайная карта. Нет карт сокровищ.
- **Нужно:** добавить таблицу/механику карт (15 обычных + 3 сокровища), логику розыгрыша по уровню.

### 2.3. Фото «до и после» для всех действий (High)
- **principe.md:** каждое действие (посадка, выращивание, изучение рецепта, переработка, животные) требует фото ДО и ПОСЛЕ.
- **Сейчас:** `StitchReport` имеет одно поле `photo_url`. Только для отчётов вышивки.
- **Нужно:** добавить `photo_before_url` + `photo_after_url` в `StitchReport`, либо отдельную модель подтверждений. Связать отчёты с конкретным действием (plot_id, production_id, animal_pen_id, recipe_id).

### 2.4. Сбор урожая → склад растений (High)
- **principe.md:** при сборе урожая растение уходит на склад игрока.
- **Сейчас:** `harvest_cell` освобождает клетку, но НЕ добавляет растения в inventory. Inventory хранит только готовые товары (products).
- **Нужно:** либо добавить склад растений (plant_id + qty в inventory), либо добавить отдельную таблицу `plant_inventory`.

### 2.5. Переработка растений в товары (производство) (High)
- **principe.md:** игрок нажимает на шатёр → видит список возможных переработок (из склада растений) → выбирает растение и количество → норма = `production_norm_per_level × qty` → фото до/после → товар на склад.
- **Сейчас:** `craft_product` просто тратит крестики и создаёт товар. Нет связи с растениями на складе, нет выбора растения.
- **Нужно:** полностью переработать `POST /productions/{id}/craft`: выбор растения со склада, расчёт нормы по уровню, списание растений, зачисление товара.

### 2.6. Настройка норм переработки по уровням (High)
- **principe.md:** админ задаёт норму на товар с растения 1 уровня, 2 уровня, 3 уровня.
- **Сейчас:** есть только `production_required` (единая норма).
- **Нужно:** добавить настройки `production_norm_lvl1`, `production_norm_lvl2`, `production_norm_lvl3`.

### 2.7. Библиотека / изучение рецептов (Medium)
- **principe.md:**
  - Страница библиотеки с иконками растений.
  - 3 нормы изучения по уровню сложности (игрок настраивает в начале).
  - Изучение: норма → фото до/после → рецепт открыт.
- **Сейчас:** отсутствует полностью.
- **Нужно:**
  - Таблица `recipes` (plant_id, product_id, required_stitches).
  - Таблица `user_recipes` (user_id, recipe_id, status: locked/studied).
  - Настройки норм изучения: `study_norm_lvl1`, `study_norm_lvl2`, `study_norm_lvl3`.
  - API: список рецептов, запрос на изучение, подтверждение изучения (фотоотчёт).

### 2.8. Скотный двор / животные (High)
- **principe.md:**
  - 8 волшебных животных, каждое даёт уникальную продукцию.
  - Игрок нажимает на пустой загон → выбирает животное → картинка пустого загона → норма на установку сенника (единая для всех) → фото до/после → загон с животным.
  - Получение продукции: бросок кубика d6 → норма = `animal_production_norm × бросок` → фото → продукция на склад.
  - Загон навсегда закрепляется за типом животного.
- **Сейчас:** модель `Animal` только как каталог. Нет загонов, нет механики.
- **Нужно:**
  - Таблица `animal_pens` (user_id, animal_id, status: empty/building/ready, accumulated, required, image_url, pen_image_url).
  - Настройки: `animal_build_norm` (единая), `animal_production_norm`.
  - API: установка загона, инвестирование в постройку, кубик + получение продукции.
  - Админка: загрузка картинок пустого загона, загонов с животными, граней кубика.

### 2.9. Система уровней и прогрессии (Medium)
- **principe.md:**
  - 0–16 уровни.
  - Условия перехода: монеты + количество грядок.
  - Каждый уровень открывает: территории, загоны, питомцев, сады, грядки новых уровней.
- **Сейчас:** `User.round` существует, но нет логики перехода. Нет таблицы уровней.
- **Нужно:**
  - Таблица `levels` (level, required_coins, required_plots, unlocks).
  - API: проверка условий, переход на новый уровень.
  - Админка: настройка уровней.

### 2.10. Достижения (Low-Medium)
- **principe.md:**
  - 20+ достижений с картинками-наградами.
  - Условия: «Первое растение», «Первый заказ», «Все шатры», и т.д.
- **Сейчас:** отсутствует.
- **Нужно:**
  - Таблица `achievements` (code, name, description, condition, image_url).
  - Таблица `user_achievements` (user_id, achievement_id, earned_at).
  - Логика проверки условий при действиях игрока.

### 2.11. Касса (Low-Medium)
- **principe.md:** касса — отдельный конверт, ставится как шатёр. Продажа излишков за ½ цены. Подсчёт монет за раунд с чеками.
- **Сейчас:** касса не реализована. Заказы дают монеты напрямую.
- **Нужно:** добавить кассу как 4-й тип постройки. Или упростить — продажа излишков через отдельный endpoint.

### 2.12. Карты сокровищ (Medium)
- **principe.md:** 3 бонусные карты сокровищ в колоде (для огромных норм, по желанию).
- **Сейчас:** нет.
- **Нужно:** добавить в механику розыгрыша карт, с особым расчётом нормы.

### 2.13. Разное количество карт для шатров (Low-Medium)

  - Шатёр портнихи: 3 карты.

### 2.14. Видео/анимации (Low — on hold)
- **principe.md:** видео перемешивания колоды, видео кубика.

### 2.18. Формула цены животного (Low)

## 4. Детальный план: Фаза 1 — Выращивание и склад

### 4.1. Количество растений при посадке
- **API:** изменить `POST /fields/{field_id}/cells/{col}/{row}/plant`.
- **Запрос:** добавить поле `qty: int = 1` (1–20).
- **Логика:** `required = crystal_norm × qty`.
- **Модель:** `Plot.qty` уже есть.
- **Фронтенд:** поле ввода количества в диалоге посадки.

### 4.2. Склад растений
- **Модель:** новая таблица `plant_inventory` (user_id, plant_id, qty). Или расширить `inventory` полем `plant_id` (nullable, взаимоисключающее с product_id).
- **API:** `harvest_cell` → добавить `+qty` растения в `plant_inventory`.
- **API:** `GET /api/farm/plant-inventory` — список растений на складе.
- **Фронтенд:** страница склада показывает и растения, и товары.

## 5. Детальный план: Фаза 2 — Карты и нормы

### 5.1. Розыгрыш карт по уровню
- **Модель:** таблица `cards` (id, kind: normal/treasure, color, count, base_value). 15 обычных + 3 сокровища.
- **Логика:** функция `draw_cards(plant_level)` → list[Card].
  - lvl1: random.sample(обычные, 1).
  - lvl2: random.sample(обычные + сокровища, 2).
  - lvl3: random.sample(обычные + сокровища, 3).
- **Норма:** сумма `crystal_norm(color, count)` по всем вытянутым картам × qty.
- **Использовать в:** `plant_on_cell`, `start_tent_build`.

### 5.2. Карты сокровищ
- **Модель:** +3 записи в `cards` с `kind='treasure'`.
- **Нормы:** админ задаёт в настройках `treasure_norm` (единая или по цветам).
- **Фронтенд:** отображение выпавших карт.

## 7. Детальный план: Фаза 4 — Производство

### 7.1. Новый craft (переработка растений)
- **API:** переработать `POST /api/farm/productions/{id}/craft`.
- **Запрос:** `plant_id` (со склада) + `qty` (сколько переработать).
- **Валидация:** на складе достаточно растений.
- **Норма:** `production_norm_lvl{level} × qty`.
- **Процесс:** создаёт stitch_report → при зачёте: списывает растения, добавляет товар.
- **Настройки:** `production_norm_lvl1`, `production_norm_lvl2`, `production_norm_lvl3`.

### 7.2. Библиотека рецептов
- **Модель:** `Recipe` (plant_id, product_id, required_stitches, level).
- **Модель:** `UserRecipe` (user_id, recipe_id, status: locked/studying/studied).
- **API:** `GET /api/library` — каталог рецептов для уровня игрока.
- **API:** `POST /api/library/{recipe_id}/study` — начать изучение (создаёт stitch_report).
- **API:** подтверждение через stitch_report → статус studied.
- **Настройки:** `study_norm_lvl1/2/3`.

## 8. Детальный план: Фаза 5 — Животные

### 8.1. Загоны для животных
- **Модель:** `AnimalPen` (id, user_id, animal_id, status: empty/building/ready, accumulated, required, pen_image_url).
- **Поле:** расширить `field_cells.kind` значением `pen` или использовать отдельную механику.
- **API:** `POST /api/animals/pens` — занять загон, розыгрыш нормы.
- **API:** `POST /api/animals/pens/{id}/invest` — вложить крестики.
- **Настройки:** `animal_build_norm` (единая норма).

### 8.2. Получение продукции
- **API:** `POST /api/animals/pens/{id}/produce` — бросок кубика (1–6).
- **Норма:** `animal_production_norm × dice_result`.
- **Процесс:** stitch_report → при зачёте: +N продукции на склад.
- **Настройки:** `animal_production_norm`.
- **Админка:** загрузка картинок граней кубика, пустого загона, загонов с животными.

## 9. Детальный план: Фаза 6 — Уровни и прогрессия

### 9.1. Таблица уровней
- **Модель:** `Level` (level: int PK, required_coins, required_plots, reward_description, unlocks_json).
- **API:** `GET /api/levels` — все уровни.
- **API:** `POST /api/levels/{n}/advance` — попытка перехода.
- **Проверка:** `user.coins >= required_coins AND count(user.plots) >= required_plots`.
- **Эффект:** `user.round = n + 1`. Разблокировка садов, загонов, питомцев.

### 9.2. Админка уровней
- CRUD для таблицы `levels`.
- Поле `unlocks_json`: что открывается (сады уровня X, +N загонов, питомцы и т.д.).

## 14. Решения по неясным моментам (согласовано с автором 2026-08-11)

1. **Фото до/после** — ✅ **Для всего.** Каждое действие (посадка, переработка, животные, изучение) требует 2 фото: до и после.
   - `StitchReport` получает `photo_before_url` + `photo_after_url`.
   - `context_type` определяет тип действия: `plant_grow`, `recipe_study`, `production`, `animal_build`, `animal_produce`, `tent_build`.
   - `context_id` связывает отчёт с конкретной сущностью.

2. **Склад** — ✅ **Общий склад с категориями.** Inventory хранит и растения (`plant_id`), и товары (`product_id`). На фронте — вкладки/фильтры «Растения» / «Товары».

3. **Грядки vs Сады** — ✅ **Одна механика.** Сады — те же клетки поля (`kind='bed'`), просто другая группа растений (`category='orchard'`). Доступность садов — по уровню игрока.

4. **Заказы** — ✅ **Авто-генерация из шаблонов.**
   - Админ создаёт шаблоны заказов, привязанные к растениям/животным.
   - При посадке растения или установке загона игра автоматически создаёт заказы по шаблонам.
   - Новая модель `OrderTemplate` (plant_id, animal_id, product_id, qty, reward_coins, customer).

5. **Касса** — ✅ **Кнопка продажи.** Без отдельной постройки. Эндпоинт `POST /api/farm/sell-surplus` — продажа излишков со склада за ½ цены заказа.

6. **Видео** — ✅ **Полноценное видео.** Админ загружает видео для:
   - Колоды карт (перемешивание + выпадение).
   - Кубика (бросок d6).
   - Модель `GameMedia` (code, kind: video, url).

7. **Зельеварение** — ✅ **Полностью.** Отдельная большая механика (см. Фазу 8 ниже):
   - 3 котла (олово/серебро/золото на 4/5/6 ингредиентов).
   - 15 рецептов (6 зелёных, 5 синих, 4 фиолетовых).
   - 15 флакончиков с зельями.
   - Заказы зелий.
   - Эффекты на 1 раунд.

## 15. Фаза 8 — Зельеварение (полная механика)

### 15.1. Модели
- **`Cauldron`** — котлы игрока (user_id, material: tin/silver/gold, capacity: 4/5/6, status: locked/empty/filling/ready).
- **`PotionRecipe`** — рецепты (code, name, level: green/blue/violet, ingredient_slots: JSON с типами ингредиентов, effect_description, reward_coins, image_url).
- **`CauldronSlot`** — слоты котла (cauldron_id, slot_index, item_type: plant/product, item_id).
- **`UserPotion`** — готовые зелья игрока (user_id, potion_recipe_id, qty).

### 15.2. Механика
- Котлы открываются по уровням игрока.
- Ингредиенты: со склада (растения + товары), 1 тайл на слот.
- Пока зелье собирается — ингредиенты забрать нельзя.
- Завершение сбора: зелье можно применить (эффект на 1 раунд) + наклейка в дневник + монеты.
- При снятии ингредиента до завершения — сбор сбрасывается.

### 15.3. API
- `GET /api/cauldrons` — котлы игрока.
- `POST /api/cauldrons/{id}/add-ingredient` — добавить ингредиент в слот.
- `POST /api/cauldrons/{id}/remove-ingredient` — убрать ингредиент.
- `POST /api/cauldrons/{id}/brew` — завершить варку (создаёт stitch_report).
- `POST /api/potions/{id}/use` — применить зелье.
- `GET /api/admin/potion-recipes` — CRUD рецептов.
